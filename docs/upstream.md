# 与上游的关系

本项目（Maa4Linux）是 [MaaAssistantArknights](https://github.com/MaaAssistantArknights/MaaAssistantArknights) 的**第三方客户端**，与上游项目及其维护者没有从属关系，也不代表上游立场。

## 我们使用上游的什么

| 上游产物 | 用途 | 更新方式 |
| --- | --- | --- |
| `libMaaCore.so` 及其运行时依赖 | 自动化引擎 | 钉在 `v6.22.0` 的 Linux 发行物，按 sha256 校验 |
| 基础资源包 | 任务图、模板、模型、数据文件 | 随安装包分发，钉在 `v6.22.0` 快照 |
| `MaaResource` 仓库（`main`） | 跟随游戏更新的资源覆盖层 | 用户触发或启动时检查，独立于客户端版本 |
| 界面文案（`zh-cn` / `en-us`） | 构建期生成文案目录 | 随引擎版本，键名保持一致 |
| 协议文档与 JSON Schema | 任务参数、回调、作业格式的依据 | 作为行为对齐的规范引用 |

## 我们不做什么

- **不修改引擎源码**，也不向上游提交针对本客户端的补丁；需要引擎行为变化时，等上游发布。
- **不重新分发引擎源码**，只按上游发行物原样携带二进制。
- **不声称对资源拥有任何权利**：模板、模型、数据与文案的版权归上游及其贡献者。
- **不把本项目的 issue 交到上游**：本客户端的崩溃、界面问题、打包问题都在本仓库报。只有能脱离本客户端复现的引擎问题，才适合按上游模板提交，并在其中注明是通过本客户端触发的。
- **不把 `MaaResource` 的更新当作客户端发版**：两者节奏不同，见 [ADR-0002](./adr/0002-three-layer-versioning.md)。

## 与其它客户端的关系

上游同时存在 WPF（Windows）、MaaMacGui（macOS）、maa-cli（Linux/macOS CLI）与 MAAUnified（Avalonia，未发布）四个客户端。本项目是第五个，定位是 **Linux 桌面的原生图形客户端**：

- 与 `maa-cli` 的分工：CLI 面向脚本与终端，本项目面向桌面日常使用；两者共用同一引擎与同一份资源，可以并存。
- 与 MAAUnified：不合并、不跟随其实现，但会关注其接口取舍；若其路线最终稳定，再评估是否共享部分抽象。

## 版本对齐与漂移检测

- **客户端行为**对齐 `v6.22.0` 的 WPF GUI；上游 `dev-v2` 与 `v6.22.0` 在该版本上界面与 ABI 完全一致，因此漂移风险低。
- **引擎**按需跟随上游 release 升级，升级前用引擎集成测试与端到端脚本验证；ABI 与回调只增不减是我们的前提，若上游破坏这一点，暂停升级。
- **资源**每周检查一次上游 `MaaResource` 的变化，若覆盖层出现新的任务类型或参数，补进"未知项"清单并排期。
- **文案**随引擎版本重新生成；上游新增的键若未被我们引用，允许闲置。

## 许可

本仓库以 AGPL-3.0 发布，与上游一致，这也是复用其资源与文案的前提。引擎与资源本身仍受上游各自的许可与版权约束。

# Maa4Linux v1 规格

- **状态**：已确认，待实施
- **对齐目标**：MaaAssistantArknights `v6.22.0`（提交 `901e01c`）的 WPF GUI 行为
- **本文档与 GitHub Issue 的关系**：Issue 是规格的发布位置，本文件是同一份内容的仓库副本

## Problem Statement

Linux 用户今天只能两条路使用 MAA：在 Wine 里跑 Windows 版，或者用 `maa-cli`。前者有大量已知问题——字体 hinting 被强制开启且 DPI 不传给 FreeType、GNOME 下 XEmbed 托盘不工作、不使用原生通知时弹窗会抢走全系统鼠标焦点、Light 主题会让部分文字颜色异常、使用原生 MaaCore 时无法自动更新。后者根本没有图形界面，任务配置只能写 TOML。

但 MAA 的引擎本身在 Linux 上是原生可用的，上游的 Linux 发行物里就带着 `libMaaCore.so` 与全部运行时依赖。缺的只是一个原生客户端。

## Solution

用 Rust + GTK4 + libadwaita 写一个原生桌面客户端，直接驱动上游 `v6.22.0` 的 `libMaaCore.so`，行为对齐上游 WPF GUI 的核心工作流：任务队列（13 张任务卡）、自动战斗（Copilot）、设置、日志与截图，以及**跟随游戏更新、独立于客户端版本**的资源更新。

引擎、基础资源与资源覆盖层都是外部依赖，客户端不包含任何自动化逻辑。GUI 行为钉在 `v6.22.0`，资源跟随游戏。

## User Stories

### 安装与连接

1. As a Linux 桌面用户, I want 用发行版方式装好后从应用菜单直接启动, so that 我不必再安装 Wine 和 Visual C++ 运行库。
2. As a Waydroid 用户, I want 选择 Waydroid 预设后地址自动填好, so that 我不必自己去容器设置里找 IP 和 5555 端口。
3. As a 使用 AVD 的用户, I want 一键刷新设备列表并选中 `emulator-5554`, so that 我不必手抄 ADB 地址。
4. As a 没有安装 platform-tools 的用户, I want 客户端内置 ADB 实现, so that 我不必额外装 adb 才能用。
5. As a 日服 / 韩服 / 美服 / 台服玩家, I want 选择我的区服, so that 模板图与关卡数据和我的游戏客户端匹配。
6. As a 连接失败的用户, I want 看到具体原因（ADB 不存在、地址不可达、分辨率不符、触控模式不可用）, so that 我能自己修好而不是面对一句"连接失败"。
7. As a 用 USB 真机的用户, I want 填写任意 `adb connect` 地址, so that 远程设备也能用。
8. As a 首次启动的用户, I want 引导告诉我需要一份 16:9 且高于 720p 的分辨率, so that 我不会因为分辨率问题误以为软件坏了。

### 任务队列

9. As a 日常玩家, I want 看到按执行顺序排列的任务卡, so that 我知道这一步点开始会发生什么。
10. As a 日常玩家, I want 单独启用或停用某张任务卡, so that 今天不想打肉鸽时不必删掉它。
11. As a 日常玩家, I want 拖拽调整任务顺序, so that 我可以让公招在理智作战之前跑。
12. As a 日常玩家, I want 展开任意一张卡就地修改参数, so that 我不用跳到别的页面。
13. As a 高级玩家, I want 从某张卡开始运行, so that 前面的步骤已经手动做完时不必重复。
14. As a 高级玩家, I want 只运行某一张卡一次, so that 临时补一次信用作战不必改整条队列。
15. As a 多用途用户, I want 复制、重命名、删除任务卡, so that 我可以维护两套打法。
16. As a 正在跑任务的用户, I want 运行期间队列被锁定并说明原因, so that 我不会在任务执行到一半时改乱参数。
17. As a 中途需要出门的用户, I want 中断后从上次完成的任务继续, so that 回来时能接着跑而不是从头再来。
18. As a 新用户, I want 每张任务卡开箱就有合理默认值, so that 我可以直接点开始而不用先读文档。
19. As a 用户, I want 每张卡标注它调用的引擎任务类型与当前生效的关键参数, so that 我知道默认值意味着什么。
20. As a 用户, I want 任务完成、失败、被停止时看到明确反馈, so that 我不会盯着屏幕猜它是不是卡住了。
21. As a 长期用户, I want 队列与参数修改后立刻持久化, so that 崩溃或断电后不必重配。

### 自动战斗（Copilot）

22. As a 抄作业用户, I want 粘贴 `maa://12345` 或关卡代号直接开始, so that 我不必下载 JSON 文件。
23. As a 抄作业用户, I want 从本地 JSON 文件导入作业, so that 没有网络的作业也能用。
24. As a 抄作业用户, I want 解析失败时看到是哪个字段出错, so that 我能判断是作业文件坏了还是客户端不支持。
25. As a 缺干员的用户, I want 追加自己的替代干员, so that 作业要求的干员我没有时仍能跑。
26. As a 抄作业用户, I want 运行中看到当前步骤、关卡名与剩余步骤, so that 我知道它有没有跑偏。
27. As a 抄作业用户, I want 作业声明的最低版本高于当前引擎时收到明确提示, so that 我不会得到一堆莫名其妙的识别失败。
28. As a 保全派驻 / 悖论模拟用户, I want 用对应的作业类型, so that 这些模式也能抄作业。

### 自动肉鸽（完整参数）

29. As a 肉鸽玩家, I want 选择主题、模式与难度, so that 我能跑当前赛季的肉鸽。
30. As a 肉鸽玩家, I want 指定分队、职业组与起手干员, so that 我不用赌开局。
31. As a 肉鸽玩家, I want 配置助战干员与好友助战开关, so that 我能用借来的核心干员开局。
32. As a 肉鸽玩家, I want 开启投资与"找存钱目标", so that 源石锭能自动存进去。
33. As a 肉鸽玩家, I want 配置坍缩范式与收藏品模式, so that 萨米与萨卡兹的机制能按我的策略处理。
34. As a 肉鸽玩家, I want 配置 BlackFlow 相关参数, so that 新主题的自动策略可用。
35. As a 肉鸽玩家, I want 运行中看到当前层数、节点类型与已用步数, so that 我能判断它是否陷在死循环里。
36. As a 肉鸽玩家, I want 肉鸽失败后不阻塞后续任务卡, so that 一次失败不会毁掉整条日常。

### 设置

37. As a 用户, I want 配置连接方式（系统 ADB 或内置 ADB、路径、地址、预设）, so that 换设备时只改一处。
38. As a 用户, I want 配置启动设置（客户端类型、自动启动游戏、账号切换）, so that 每次运行不必手点。
39. As a 用户, I want 配置运行设置（关卡、次数、理智药剂、碎石上限）, so that 理智用完时行为符合我的预期。
40. As a 用户, I want 配置性能设置（任务间隔、截图间隔、CPU/GPU 推理）, so that 慢机器不卡、快机器更快。
41. As a 无障碍用户, I want 界面跟随系统深浅色与字体缩放, so that 我不必忍受被写死的配色。
42. As a 用户, I want 控制哪些事件触发桌面通知, so that 长任务完成时我能收到提醒而不被每一步打扰。
43. As a 从 Wine 版迁移的用户, I want 导入旧的配置, so that 我不必把十几张任务卡重新配一遍。
44. As a 报障用户, I want 在"关于"里看到客户端、引擎、资源与服务端四者的版本, so that 我能一次说清楚我的环境。

### 日志与截图

45. As a 用户, I want 实时看到任务链与子任务的日志, so that 我知道它现在在干什么。
46. As a 用户, I want 按级别、任务类型过滤日志, so that 报错时能快速定位。
47. As a 用户, I want 展开单条日志查看原始 JSON, so that 我能确认引擎到底返回了什么。
48. As a 用户, I want 在掉落与公招结果上看到缩略图, so that 我不必读文字就知道掉了什么。
49. As a 用户, I want 运行中看到最新一帧画面, so that 截图卡住时我能一眼看出来。
50. As a 用户, I want 导出日志与截图, so that 我能把证据贴进 issue。
51. As a 用户, I want 日志面板不因为刷屏而卡住界面, so that 跑一晚上之后界面仍然可用。

### 资源更新

52. As a 用户, I want 手动点"检查资源更新", so that 新活动开始时我能立刻拿到新数据。
53. As a 用户, I want 启动时静默检查并在有新版本时提示, so that 我不必自己想起这件事。
54. As a 用户, I want 看到资源版本对应的游戏活动名, so that 我知道这份资源是不是跟得上游戏。
55. As a 用户, I want 更新失败时保留旧资源并告诉我原因, so that 一次下载失败不会让软件变得不能用。
56. As a 用户, I want 更新在下一个任务开始时才生效, so that 正在跑的任务不会中途换掉数据。
57. As a 用户, I want 更新后能回滚到上一份资源, so that 新资源出问题时我能自救。

### 协作

58. As a 贡献者, I want 一条命令就把引擎与资源装齐, so that 我不必读长篇构建文档就能跑起来。
59. As a 贡献者, I want 在没有设备的情况下启动界面看效果, so that 我能改 UI 而不必先配 Waydroid。
60. As a 报障用户, I want 提交 issue 时附带的版本信息是自动生成的, so that 维护者不必反复追问。

## Implementation Decisions

### 版本模型（三层，彼此独立）

1. 客户端行为对齐目标钉在 `v6.22.0`；引擎二进制钉在 `v6.22.0` 的 Linux x86_64 发行物；基础资源钉在 `v6.22.0`；资源覆盖层跟随上游 `MaaResource` 的 `main` 分支。
2. 这三者写在同一个版本清单里但分成四个字段（`gui_target`、`engine`、`resource_base`、`resource_channel`），由构建脚本与打包清单共同读取，禁止在别处硬编码版本号。
3. 资源覆盖层不会要求更新引擎：上游 `MaaResource` 只镜像"与 MaaCore 版本无关"的文件（关卡数据、干员与物品数据、热修 OCR、`template/items`、`template/infrast`、关卡格子），任务图、模型与 `platform_diff` 都不在其中。因此引擎可以长期停在 `v6.22.0`。

### 引擎集成

4. 引擎以同进程动态加载方式引入，所有 FFI 调用集中在一个 crate 内，其它 crate 不得出现 `unsafe`。加载失败、符号缺失、库版本不符都在启动时给出可读错误，而不是 panic。
5. 只绑定实际使用的 C 接口：设置用户目录、加载资源、静态选项、创建/销毁实例、实例选项、异步连接、连接附加参数、追加任务、修改任务参数、开始/停止/运行中/已连接/回主界面、异步点击、异步截图、取 PNG、取 BGR、取 UUID、取任务列表、取空尺寸、取版本、写日志。Windows 专用的窗口绑定接口与已废弃的同步连接接口不绑定。
6. 引擎回调在引擎自己的线程上触发，必须立刻转交给 GTK 主循环，不得在回调里做任何阻塞或重活；回调里发生的任何异常都被吞掉并记录，不得跨 FFI 边界展开。
7. 回调消息在边界上保持"原始事件"形态：消息编号 + `what` 字符串 + 原始 JSON 值。界面按需把认识的 `what` 反序列化成具体结构；不认识的 `what` 原样进日志并提供 JSON 查看，不丢弃、不 panic、不当作错误。
8. 启动顺序固定为：设置用户目录 → 加载基础资源 → 加载覆盖层 →（区服层）→ 创建实例 → 设置静态/实例选项 → 连接。任一步失败都停在界面里并说明是哪一步、为什么。
9. 引擎事件与界面之间只通过一个抽象接口传递（连接、追加任务、改参数、开始、停止、取图、事件流），使引擎可以被一个内存里的假实现替换。这条缝是 v1 唯一的集成缝。

### 资源分层

10. 基础资源随安装包分发、运行期只读，位置按"显式环境变量 → 安装目录的共享数据目录 → AppImage 内路径 → 开发期仓库目录"依次探测；可写资源在 XDG 数据目录下，首次运行不需要把 256 MB 基础资源复制一份。
11. 叠加顺序与上游一致：基础主资源 → 可写主覆盖 → 区服基础资源 → 区服覆盖。引擎的"加载资源"接口接收的是**包含 `resource/` 的那一层目录**，不是 `resource/` 本身。
12. 资源版本以覆盖层里 `resource/version.json` 的 `last_updated` 为唯一标记，按 UTC 解析；缺失或格式不符时视为"未知版本"，允许运行但禁止自动更新提示。
13. 资源更新只走 GitHub 的全量覆盖包（`MaaResource` 主分支归档）；下载后先解压到临时目录，按结构校验（版本文件、任务目录、模板目录、关卡数据非空），再按文件合并、**`version.json` 最后写入**，最后原子切换"当前覆盖目录"指针，保留上一份用于回滚。
14. 资源更新由独立的更新源抽象承担，v1 只实现 GitHub 全量通道；MirrorChyan 与 `api.maa.plus` 热修通道预留为同一抽象的第二个实现，加载器的多目录叠加设计已为它们留好位置。
15. 正在运行任务时检测到新资源只记录并提示，实际切换发生在下一次任务开始前。

### 任务队列与任务卡

16. 任务队列是客户端概念：一张张任务卡按顺序排列，逐张作为一条任务链下发给引擎。工具任务（公招识别、仓库识别、抽卡等）没有对应的引擎任务类型，v1 不做。
17. 13 张任务卡与上游一致：理智作战、干员养成、公开招募、开始唤醒、基建换班、信用收支、领取奖励、自动肉鸽、更新数据、库存保持、更换主题、自定义、结束后动作。
18. 每张卡的参数模型显式声明已知字段，同时保留原始 JSON 透传：不认识的键在保存与回写时原样保留，避免上游新增参数被我们吞掉。
19. 队列中遇到未知任务类型时渲染为只读占位卡：可加入、可运行（按默认参数下发）、卡上标注"需要更新客户端"。
20. 自动肉鸽参数做完整对齐，不做子集：主题、模式、难度、分队、职业组、起手干员、助战、投资、找存钱目标、坍缩范式、收藏品模式、BlackFlow 相关项、最大次数等，逐项对照上游任务配置与文档。
21. 任务队列交互：启用开关、拖拽排序、从某卡开始、只跑一次、复制、重命名、删除、运行中锁定（灰化 + 行内提示，不弹确认框）。

### 界面

22. 使用 GTK4 + libadwaita（最低 GNOME 46 / libadwaita 1.5），Wayland 优先，X11 回退也必须可用。
23. 主窗口为三屏导航：任务队列、自动战斗、设置。工具箱不在 v1。
24. 组件模型采用消息驱动的组件框架，一张任务卡对应一个组件；自绘控件（日志卡、图表）用原生 GTK 控件子类化实现，不进组件树。
25. 设置页使用 libadwaita 的首选项页形态，v1 出 8 个：配置档（只显示 `default`）、性能、运行、连接、启动、界面、通知、关于。
26. 日志区为卡片流：时间、级别、任务链/子任务、标题、可选缩略图、可展开原始 JSON；支持按级别与任务类型过滤、关键字搜索、清空、导出。缩略图只挂在认可的事件上（关卡掉落、公招结果、战斗步骤）。
27. 运行中在日志区上方显示最新一帧截图，可关闭；不做截图历史与独立预览窗口。
28. 桌面通知使用 GNotification，保证在 Flatpak 沙箱内也能工作；每个通知类别可单独开关。
29. 单实例：以应用 ID 占用会话总线名，第二次启动激活已有窗口。
30. 界面文案不手写：构建期从上游 `v6.22.0` 的 `zh-cn` 与 `en-us` 语言文件生成文案目录，键名保持完全一致；v1 只发布简体中文与英文。CI 检查"代码里引用的键必须存在"，未使用键允许存在。
31. 界面语言跟随系统区域设置，无法匹配时回退英文。

### 配置与迁移

32. 配置放在 XDG 目录，磁盘布局从第一天就是多配置档（每档一个目录），v1 界面只暴露 `default`，切换界面留到后续版本。
33. 首次启动时若发现 Wine 版 MAA 的配置，提供一次性**有损导入**：映射队列（类型、顺序、启用状态、主要参数）、连接与启动设置，其余键丢弃并列出报告。导入失败不得影响客户端启动。
34. 配置读写必须容忍未知字段与缺失字段（默认值补齐），不得因为一个键写错就丢掉整份配置。

### 打包与分发

35. 应用 ID 为 `io.github.imyifeng.Maa4Linux`，可执行文件名 `maa4linux`，桌面文件、图标、AppStream 元数据与 Flatpak manifest 共用同一 ID。
36. v1 只出 x86_64：AppImage 为主，Flatpak 与 AUR 同批次，三者从同一份版本清单生成，避免两套校验值。
37. AppImage 内嵌基础资源与引擎及其全部运行时依赖；Flatpak 沙箱内默认使用内置 ADB 实现并要求网络权限，非沙箱环境默认使用系统 ADB。
38. 客户端不自带更新机制：AppImage 由用户替换、AUR 由包管理器、Flatpak 由运行时。资源更新与客户端更新彻底分离。

### 依赖与工程

39. 工作区按"缝"切分：引擎集成（唯一 `unsafe`）、领域模型（任务、参数、设置、配置档、导入，纯逻辑可全量单测）、资源（分层、版本、更新通道，唯一网络面）、界面（可执行程序）、构建脚本。界面只依赖领域模型的公开类型，不依赖资源 crate 的内部。
40. 网络、解压、配置解析之外的依赖保持克制；日志使用结构化、可按级别与目标过滤、写入文件并轮转的实现。
41. 引擎与基础资源不进版本库：由构建脚本按版本清单拉取并校验 sha256，失败时给出明确的手动放置说明。

## Testing Decisions

**什么算好测试**：只断言外部可观察行为——任务卡序列化出的 JSON 结构、配置往返、资源层叠后的可见文件、事件流驱动出的界面状态；不断言内部实现细节与控件树结构。

**测试缝**（两条，已确认为 v1 全部）：

1. **引擎集成缝**：内存里的假引擎实现同一抽象接口。它按脚本回放引擎事件、按脚本返回截图，使队列、日志、Copilot、肉鸽进度、错误路径全部可以在没有设备的情况下测。
2. **资源源缝**：资源更新通道抽象后的实现，可在测试里指向本地目录/本地服务器，使"检查 → 下载 → 校验 → 合并 → 回滚"整条路径可测。

除此之外只有纯函数，不需要额外的缝。

**分层**：

- **单元测试**：领域模型（13 张任务卡的参数往返与未知键保留、配置档读写与容错、Wine 配置导入、资源版本比较、i18n 键解析）。
- **界面冒烟**：在无头合成器下渲染三屏与 13 张卡，用假引擎回放一串真实事件（关卡掉落、公招结果、任务链开始/完成/失败、子任务额外信息），断言不 panic、日志卡数量正确、缩略图占位出现。CI 中执行。
- **引擎集成**：真实引擎只测到"加载资源 → 创建实例 → 收到连接失败事件"这一级，不需要设备。CI 中执行。
- **设备级端到端**：写成可手动运行的脚本，检测到 Waydroid / AVD 时才跑，不进 CI。

**先例**：本仓库尚无测试代码；上游 `test/` 是空子模块，无可复用先例。第一条测试就是以假引擎驱动的界面冒烟，它同时充当"缝可用"的证明。

## Further Notes

### v1 验收标准

在一台 Waydroid（1280×720）上的普通 Linux 桌面上，从冷启动开始：配置连接 → 跑完"开始唤醒 → 理智作战（某关 ×3）→ 公开招募 → 基建换班 → 信用收支 → 领取奖励"整条队列 → 中途中断并续跑 → 手动检查并应用一次资源更新 → 提交一份 `maa://` 作业并在肉鸽模式下各跑一次；全程界面不崩溃、日志与掉落缩略图正确、应用与重开后队列与参数保留。

### 实施顺序（纵向切片，不改变 v1 范围）

工作按纵向切片推进：每条切片从界面到引擎完整贯通、可独立演示，并注明它依赖哪些切片。切片与其阻塞关系以 issue #1 的子票为准，顺序为：

1. 冷启动到可读错误
2. 连接受控端
3. 跑通一张卡：开始唤醒
4. 日志卡片流与截图、理智作战卡、日常四张卡、其余六张卡、队列编排（并行）
5. 肉鸽：常用参数 → 高级参数
6. 自动战斗（Copilot）
7. 资源更新
8. 设置补全与 Wine 配置迁移
9. 首个可安装产物（AppImage）→ Flatpak 与 AUR
10. 端到端验收

### 已知风险

- **肉鸽参数完整性**是 v1 最大的单卡工作量，且上游参数会随赛季演进；以"逐项对照表"驱动，避免遗漏。
- **引擎崩溃**会带走整个界面（同进程决策的直接后果）。缓解：所有任务状态持久化，重启后可续跑；缝已留好，真需要时可切到独立进程。
- **Wayland 下的通知与热键**受桌面环境限制；v1 只用 GNotification，不做全局热键，因此不受影响。
- **上游资源格式演进**可能引入我们未实现的任务类型；占位卡与未知键透传已覆盖此风险，但需要持续观察。
- **Flatpak 内的 ADB 与设备可见性**：内置 ADB 实现 + 网络权限已覆盖网络设备，USB 真机在沙箱内可能不可达，需在文档中如实说明。

# 三层版本：客户端、引擎、资源各自独立

客户端行为钉在上游 `v6.22.0`，引擎二进制也钉在 `v6.22.0`，但游戏资源跟随游戏更新、不受这个钉版约束：基础资源随安装包分发，资源覆盖层来自上游 `MaaResource` 的 `main` 分支，其版本标记是 `resource/version.json` 的 `last_updated`。

它之所以可行，是因为上游的资源覆盖层只镜像"与 MaaCore 版本无关"的文件（关卡数据、干员/物品数据、热修 OCR、`template/items`、`template/infrast`、关卡格子），任务图、模型与平台差异都不在其中。因此"游戏更新了但客户端不必更新"是上游本来就成立的模型，不是我们的妥协。

## Consequences

- 会出现"客户端版本 6.22.0、资源版本 2026-12-xx"的常态组合，报障时必须同时收集三者版本。
- 资源可能出现客户端尚不认识的任务类型或参数；界面用占位卡与未知键透传降级，而不是拒绝加载。
- 资源更新不会构成升级引擎的理由，引擎升级是独立决策。

## Considered Options

- **整体随上游 release 一起升级**：被否决——游戏资源每天都可能变，把客户端更新绑上去会让用户在新活动当天用不了新数据。

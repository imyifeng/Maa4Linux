# 客户端边界：只重写客户端，引擎保持为外部依赖

MAA 的引擎（MaaCore）本身跨平台，Linux 发行物里已经带着可用的 `libMaaCore.so` 与全部运行时依赖；不跨平台的只有 WPF 编写的 GUI。因此本项目只实现**客户端**——调用引擎的冻结 C 接口、渲染其事件与截图——而不重写引擎。真正的替代方案是用 Rust 重写整个引擎（任务图解释器、视觉识别、OpenCV 与 ONNX 的逐位对齐、约 10 万行 C++），那是数年的工作量，且没有客观标准判断"是否还原了所有功能"。

## Consequences

- 客户端的正确性依赖引擎的行为，调试时必须在两者之间定位；`what` 字符串与 JSON 结构因此成为必须稳定的契约。
- 引擎崩溃会带走客户端；任务状态必须持久化到足以续跑的程度。
- 上游的引擎修复与视觉改进可以直接受益，不需要我们自己移植。
- "移植"在本项目中始终指客户端行为的对齐，而不是引擎的再实现。

## Considered Options

- **分层重写引擎**（先做客户端，再逐块用 Rust 替换引擎）：被否决——它把两件无关的事绑在一起，且差分测试的成本远高于收益。

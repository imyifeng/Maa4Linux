# 同进程加载引擎，并在其上留一条可替换的缝

引擎通过动态加载在客户端进程内使用，与上游所有客户端（WPF、macOS、maa-cli）一致。收益是没有 IPC、截图是内存拷贝、部署只有一个可执行文件加一组 `.so`；代价是引擎的段错误会带走整个界面。

为了不让这个代价变成不可逆，所有引擎调用集中在一个 crate 内，并通过一个抽象接口（连接、追加任务、改参数、开始/停止、取图、事件流）暴露给上层。独立进程实现可以在不触碰界面代码的前提下后补；同一个抽象也是 v1 全部界面测试所用的假引擎。

## Consequences

- 所有 `unsafe` 只允许出现在这个 crate；FFI 边界的 panic 必须被拦截。
- 任务状态需要持久化到"重启后能续跑"的程度，作为崩溃的兜底。
- 引擎回调在自己的线程上触发，必须立刻转交主循环，回调内不得阻塞。

## Considered Options

- **一开始就做独立进程（sidecar）**：被否决——IPC、共享截图、多一个可执行文件的复杂度在 v1 换不来相应的收益，而崩溃隔离可以靠缝隙补齐。

# 界面采用 GTK4 + libadwaita，组件用消息驱动模型，界面结构用 Blueprint 声明

要移植的界面是表单密集型：13 张任务卡、4 个屏幕、15 个设置节，上游用 MVVM（Stylet）组织。我们采用消息驱动的组件框架（Relm4）来承载"组件即一张任务卡"的结构，并用 Blueprint 声明界面结构，使布局改动不需要写 Rust；日志卡、图表这类自绘控件用 GTK 控件子类化实现。

## Consequences

- 最低要求 GNOME 46 / libadwaita 1.5，放弃更老的发行版。
- 组件树需要克制：只有"一张任务卡"这种有独立状态与消息的单元才做组件，避免演变成与上游一样的深层嵌套。
- 编译时间比裸 gtk4-rs 长，这是换取结构一致性的代价。

## Considered Options

- **裸 gtk4-rs + Blueprint**：更接近 GNOME 官方写法、编译更快，但要自己搭状态共享与信号连线，在 13 张表单卡的规模上会重复劳动；作为自绘控件的实现方式保留。
- **纯 builder 构建界面**：被否决——界面结构会散落在代码里，难以维护。
